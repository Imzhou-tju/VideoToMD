# 前景物体过滤：锁定 PPT 区域 + 转成正对

调研时间：2026-10-06
范围：通义听悟流程第 2 步「前景物体过滤」能不能借手机相机文档扫描的做法，自动锁定画面中 PPT 所在的区域，并把它矫正成正对视角

---

## 一、先补一个遗留问题：固定间隔采样的间隔是多少

**官方没给数字。**

阿里官方技术文章《2024 通义语音 AI 技术图景》原文只有这一句：

> 具体为以固定时间间隔从视频中采集视频帧得到视频帧序列，首先进行前景物体过滤，之后依据运动和静止事件检测结果锚定 PPT 切换的时间戳……

全文没有出现任何秒数、帧率、采样间隔。阿里云帮助中心的 API 文档也没给。**这个数字是通义没有公开的。**

网上能查到的具体数字全部是第三方实现，不是通义的数值：

| 出处 | 数值 | 可信度 |
|---|---|---|
| CSDN 教程《3步实现视频PPT智能提取》（2026-03） | 默认 0.5 秒/帧，用 FFmpeg 抽帧 | 第三方教程，与通义无关 |
| claude-watch（开源） | 场景检测为主，长静止段每 45 秒强制补一帧 | 开源项目，与通义无关 |
| 掘金《多模态视频理解工程》 | 举例 "1 帧/5 秒"，10 分钟视频采 120 帧 | 作者自己的例子，与通义无关 |

能确定的是三个约束条件，可以反推一个合理值：

1. 官方写了第 4 步「时间戳校准」，说明采样帧和真实切换点之间存在最大一个采样间隔的误差，需要回退修正。**间隔越大，校准这一步越重要。**
2. 要能锚定「静止窗口的起点」，间隔必须明显小于一页 PPT 的最短停留时间。PPT 最短停留通常几秒，所以间隔应该在 1 秒量级或以下。
3. 后面要做前景过滤和运动/静止事件检测，都是逐帧计算，间隔太小计算量线性上升。

**结论：自己实现就取 0.5~1 秒，不要照抄任何"官方 0.5 秒"的说法，那个数字没有官方出处。**

## 二、先判断要不要做：大多数网课视频根本不需要透视矫正

这是最重要的一条，先说清楚。

网课视频按拍摄方式分两类，处理方式完全不同：

| 类型 | 画面特征 | 需要锁定区域吗 | 需要透视矫正吗 |
|---|---|---|---|
| **录屏**（讲师用 OBS、Zoom 录屏，或 PPT 自带录屏） | PPT 铺满整帧，本来就正对，无透视变形 | 不需要，整帧就是 PPT | 不需要 |
| **翻拍 / 教室实录**（摄像机拍投影幕布、拍白板、手机拍屏幕） | PPT 是画面里的一个四边形，可能倾斜、可能被讲师挡住 | 需要 | 需要 |

**用户的输入如果是录屏，做透视矫正是负收益**：投影变换要重采样，会让文字边缘插值变糊，直接拉低后面 OCR 的准确率。录屏帧直接进 OCR 就行。

所以第一步不是"锁定区域"，而是"判断这一帧是不是已经正对"。判断方法很便宜：

```python
# 检测到的四边形如果几乎就是整帧，说明是录屏，跳过矫正
def is_already_frontal(quad, frame_w, frame_h):
    area_ratio = cv2.contourArea(quad) / (frame_w * frame_h)
    # 四个角点与画面四角的距离，全部小于短边的 2%
    corner_gap = max(dist(q, c) for q, c in zip(order_points(quad), frame_corners(frame_w, frame_h)))
    return area_ratio > 0.90 and corner_gap < 0.02 * min(frame_w, frame_h)
```

判定为正对就直接进 OCR；判定为翻拍才走锁定 + 矫正。**这一步漏掉，后面所有矫正工作都是在给已经正对的画面添噪声。**

## 三、手机相机文档扫描做了什么

iOS 备忘录扫描、扫描全能王、Office Lens 这条技术线的标准做法，OpenCV 就能完整复刻：

```python
gray  = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
blur  = cv2.GaussianBlur(gray, (5, 5), 0)
edged = cv2.Canny(blur, 15, 45)                      # 高阈值约为低阈值的 2~3 倍
cnts  = cv2.findContours(edged, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)[-2]
cnts  = sorted(cnts, key=cv2.contourArea, reverse=True)[:3]

for c in cnts:
    peri   = cv2.arcLength(c, True)
    approx = cv2.approxPolyDP(c, 0.05 * peri, True)  # 逼近精度取周长的 5%
    if len(approx) == 4 and cv2.contourArea(approx) > 0.2 * img.shape[0] * img.shape[1]:
        quad = approx
        break

rect = order_points(quad.reshape(4, 2))              # 必须排序，否则变换后图像会严重扭曲
M    = cv2.getPerspectiveTransform(rect, dst)
warp = cv2.warpPerspective(img, M, (max_w, max_h))
```

四个角点的排序规则（顶点顺序错了图像会拧成麻花）：

```python
def order_points(pts):
    rect = np.zeros((4, 2), dtype="float32")
    s = pts.sum(axis=1)        # x + y
    rect[0] = pts[np.argmin(s)]   # 左上：x+y 最小
    rect[2] = pts[np.argmax(s)]   # 右下：x+y 最大
    d = np.diff(pts, axis=1)      # y - x
    rect[1] = pts[np.argmin(d)]   # 右上：y-x 最小
    rect[3] = pts[np.argmax(d)]   # 左下：y-x 最大
    return rect
```

这个排序法在倾斜不超过 ±45° 时稳定有效，超过之后 x+y 最小的点可能变成左下角，要用凸包加角度排序。

两个容易踩的工程细节：

- **面积阈值不要写死像素值。** 教程里常见的 `area > 30000` 是 640×480 分辨率下的经验值，换分辨率就失效。写成图像总面积的比例。
- **文字会干扰边缘检测。** LearnOpenCV 的做法是先做形态学闭运算把文字抹掉，得到一张"空白页"，再拿这张空白页去找边：

```python
kernel = np.ones((5, 5), np.uint8)
blank  = cv2.morphologyEx(img, cv2.MORPH_CLOSE, kernel, iterations=3)
```

## 四、视频场景比手机拍照难在哪，怎么补

手机扫一张文档和从视频里锁定 PPT 区域，看起来是同一件事，实际有四条差异，每一条都要单独处理：

| | 手机拍一张 | 视频里锁定 |
|---|---|---|
| 交互 | 用户会主动对准，拍歪了可以重拍，有预览让用户确认 | 无人参与，错了也没人纠正 |
| 数量 | 一张 | 几万帧，结果必须跨帧一致 |
| 干扰 | 桌面背景，干净 | 讲师在前面走动、幕布边框和墙面对比度低 |
| 相机 | 手持，但只在按快门那一刻 | 可能整段都在轻微抖动 |

对应的四条补法：

### 4.1 不要逐帧检测，检测一次全局复用

摄像机固定的话，透视关系在整个视频里是同一个。微软 / 德州大学的白板专利（WO2017053032A1）和另一份智能演示专利（WO2020190547A1）都写明了这一点，WO2020190547A1 原文：

> once the quadrilateral edges of the board have been detected, the same transform can be used for all consecutive frames in the video stream
> 检测到板的四条边之后，同一个变换可以复用到视频流后续所有帧

**homography 只算一次，后面每帧直接按这个矩阵重采样。** 这不是省计算量的问题，是逐帧检测会让每帧的四边形都轻微抖动，矫正出来的图会抖。

需要处理相机移动的情况：lecture2notes 的检测方法是 ShiTomasi 角点 + Lucas-Kanade 光流，**只在图像边框区域取特征点**——中心是 slide 内容会变、底部可能有讲师的头会动，都不能代表相机运动。平均位移超过 10 像素判定相机移动，这时候原来的 ROI 作废，要重新算。

### 4.2 跨帧投票，用中值把被遮挡的帧剔除

单次检测可能被某个站在幕布前的讲师干扰。做法是对多个采样帧各跑一次检测，再对结果取中值：

```text
1. 每 10 秒取一帧，取 30 帧
2. 每帧独立跑四边形检测，得到 30 组角点，每组内部按 order_points 排序
3. 对 30 组角点的每个对应位置取坐标中位数
4. 把角点与中位数距离超过画面短边 5% 的帧判为离群，剔除后重新取中位数
```

人站着的那些帧会给出偏离的四边形，被第 4 步投票干掉。中国专利 CN201711378173 用的是同一思路的变体：统计所有候选四边形宽高比的众数，选最接近众数的那个（因为幕布宽高比在整段视频里是不变的）。

### 4.3 用干净帧做模板，把有人帧对齐过去

lecture2notes 的做法（doc/end-to-end/perspective-cropping.rst）：

它先把帧分成两类，`slide`（纯幻灯片）和 `presenter_slide`（有人在画面里）。当检测到一帧 `presenter_slide` 时，用 ORB 提取特征点、FLANN 做匹配，和时序上最近的 `slide` 帧配准。匹配点数超过阈值就认为两帧是同一页，然后用 RANSAC 算出来的变换把 `presenter_slide` 裁成只含 slide 的区域。

它还做了一个"内容增量"判断：对两张图做膨胀、找轮廓、算轮廓总面积，如果后者比前者多出 γ% 以上，就认为这一页新增了内容（比如动画逐条出现的要点），保留内容更多的那帧。

**这条对网课很实用**：讲师站在 PPT 前面讲的时候，画面是 `presenter_slide`；他走开之后是干净的 `slide`。用干净帧当模板，能把有人帧矫正回来，等于多救回来一批帧。

### 4.4 用形态学相减把遮挡物挖掉

kmel 期刊论文《Automatic Extraction of Slides from Lecture Videos》给的链路，专门处理"人的轮廓被包进 slide 区域"的问题：

```text
(a) Canny 边缘检测
(b) 膨胀，让画面里的主要形状连成一片
(c) 填充连通域，取最大的那个连通域（此时人和 slide 是连在一起的）
(d) 把 (b) 和 (c) 两张二值图相减，得到画面里真正可见的 slide 区域
(e) 在 (d) 里再取一次最大连通域，再膨胀一次补偿相减时丢掉的边缘
(f) 用 (e) 当 mask，从原图取出 slide 区域像素
```

另外一条路线是时间中值背景建模（WO2017053032A1）：多帧之间找变化，判定属于"人"的像素，用白板最近的像素值替换掉。这个方法还能顺便把讲师从画面里抹掉。

### 4.5 深度学习路线（成本最高）

| 做法 | 出处 | 成本 |
|---|---|---|
| 语义分割三分类（前景人 / 板 / 背景），输出分类图后按上右下左四个方向分别跑 RANSAC 拟合直线，取交点当四边形的第一个估计，再迭代剔除外面 | WO2020190547A1 | 要训练分割模型（MobileNetV2 编码器-解码器，输入降采样到 288×160） |
| YOLOv7 直接检测投影屏位置 | Purushotham 等 2024（i-manager's Journal on FET） | 要标注 2000 帧，增强到 5000 张 |

这两条都得先有数据和训练。**不建议一开始上。**

## 五、透视矫正本身：homography 够不够

**够。投影幕布和白板是平面，平面到平面就是单应性变换，4 对点 8 个自由度，一个 3×3 矩阵就完事。**

不需要 DocUNet / DewarpNet。这两个是给**卷曲纸张、书页**用的——纸张本身不平，有折痕和弯曲，是三维形变，所以要回归 3D 坐标图（DewarpNet 的 shape network 输出每像素的 X,Y,Z）。投影幕布没有这个问题。

判断标准：

| 场景 | 形变类型 | 用什么 |
|---|---|---|
| 拍投影幕布、拍白板、拍液晶屏 | 平面 → 平面投影 | `getPerspectiveTransform` + `warpPerspective` |
| 拍摊开的书、拍有折痕的纸 | 三维曲面形变 | DocUNet（2D 位移场）或 DewarpNet（3D 坐标图） |

DewarpNet 的效果数据（供参考，但本项目用不上）：4K 图 32ms，Tesseract OCR 的字符错误率下降 42%。代价是它只有推理代码开源，训练代码和 Doc3D 数据集的生成流程不开放，而且它明确说明对遮挡敏感。

## 六、矫正完之后还要做增强

透视变换输出的还是原图质量的彩色图，直接OCR 效果不好。手机扫描 App 都会再做一层：

```python
warped_gray = cv2.cvtColor(warped, cv2.COLOR_BGR2GRAY)
_, scanned  = cv2.threshold(warped_gray, 0, 255, cv2.THRESH_BINARY | cv2.THRESH_OTSU)
```

投影翻拍有个手机拍照没有的问题：**投影仪的光照不均**（中间亮四周暗）和**摩尔纹**（拍液晶屏时）。均匀光照用自适应阈值（`adaptiveThreshold`）比全局 Otsu 好；摩尔纹要在抽帧前做一次低通或者中值滤波。

增强只影响 OCR 输入，**笔记里展示给用户的图应该用矫正后未二值化的原图**，二值化图黑白分明但看着难受。

## 七、对 AIVideo 的落地顺序

按成本从低到高，前三步建议做，后两步按需：

| 级别 | 做什么 | 解决什么 | 成本 |
|---|---|---|---|
| **L0** | 帧类型判定，正对就直接跳过矫正 | 避免给录屏帧引入插值模糊 | 几行代码，必须做 |
| **L1** | 跨帧投票锁定四边形 + 一次 homography 全局复用 | 翻拍视频里找到 PPT 区域并矫正，跨帧一致性 | OpenCV，中等 |
| **L2** | 形态学相减剔除遮挡 + 按可见面积选最干净帧 | 讲师挡住 PPT 时仍能取到完整页 | OpenCV，中等 |
| L3 | ORB + RANSAC 用干净帧配准有人帧 | 救回被人挡住的帧 | 计算量大，按需 |
| L4 | 语义分割三分类 / YOLO 检测屏幕 | 前四步都失效时的更强手段 | 要训练数据，暂不做 |

选关键帧这一步可以顺带做掉：kmel 论文对比过，用 2D 小波分解（Daubechies）的能量百分比选帧，比单纯数 mask 里非零像素的个数效果好，因为后者没有考虑画面上到底有没有文字。

**明确不做的事**：不引入 DewarpNet / DocUNet（平面场景用不上，且推理代码之外的东西不开源）；不逐帧跑四边形检测（会让结果抖动）。
